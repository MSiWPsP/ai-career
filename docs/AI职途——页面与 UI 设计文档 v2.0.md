## 1. PRFAQ：让职业成长成为每天可执行的工作流

### 1.1 产品发布说明

**AI职途发布全新的职业成长工作台，让大学生从“我该做什么”直接走到“我今天做什么”。**

高校学生面对职业选择时，常常拥有大量零散信息，却缺少一条能根据自身情况持续调整的行动路线。课程、项目、面试题、职业建议散落在不同平台，用户很难判断自己的真实水平，也难以把一次面试暴露的问题转化为下一阶段的学习任务。AI职途把职业画像、规划、任务、模拟面试、能力诊断和重新规划连接在同一条成长链路中，并在每次进入系统时优先呈现当前目标、最近变化与下一步行动。

V2 界面不再依靠大面积渐变、光晕或装饰性“AI 科技感”吸引注意力，而是采用企业蓝白视觉、清晰的编辑式排版和稳定的数据密度，让用户感到自己正在使用一套可信、专业、可长期积累的职业成长工具。两个 Agent 仍具有清楚的身份：职业规划师负责判断方向与拆解路线，模拟面试官负责检验与反馈。机器人头像只作为角色识别点出现，内容和行动始终是页面主角。

用户首次进入系统后，可以完善职业画像并生成第一版规划；之后在首页看到目标岗位、任务进度、能力概览和最近面试结果。职业规划师对话页将当前画像、技能和规划上下文放在可见位置，帮助用户理解建议来源；模拟面试页以安静、稳定的问答环境呈现，不在过程中泄露内部评分。面试结束后，报告把结论、证据、薄弱项和行动建议按阅读顺序组织，并可基于本次结果重新规划。

本次改版成功的标志不是“页面更炫”，而是用户能在数秒内回答三个问题：我的目标是什么、我现在处于什么状态、我下一步应该做什么。平台最终希望帮助学生形成一种持续成长习惯：记录真实情况，执行小步任务，用模拟面试检验，再根据数据调整路线。

### 1.2 目标用户

- 核心用户：在校大学生、应届毕业生、实习与校招准备阶段学生。
- 典型状态：方向不够清晰、学习内容零散、缺少真实面试训练、无法判断能力变化。
- 使用环境：以桌面端深度使用为主，移动端用于查看任务、状态和简短对话。

### 1.3 关键功能

1. 结构化职业画像与技能记录。
2. 有业务上下文的职业规划咨询与版本化规划。
3. 可执行的阶段成长路线和任务管理。
4. 动态追问的模拟面试与结构化报告。
5. 能力变化可视化与面试反馈驱动的重新规划。

### 1.4 差异化优势

- 不止提供一次性建议，而是形成“画像—规划—行动—检验—调整”的闭环。
- 两个 Agent 分工明确，通过真实业务数据协作，不把所有能力混成一个聊天框。
- 规划、任务、面试与能力变化都可追溯，用户能看到成长依据。
- 界面以决策效率为目标，AI 身份明确但不喧宾夺主。

### 1.5 成功指标

- 用户进入首页后能在 10 秒内定位当前目标和下一项行动。
- 职业画像、规划、任务、面试、报告主链路无信息断点。
- 核心页面在加载、空数据、失败、完成状态下都有明确反馈与下一步。
- 1280、1440、1920 像素桌面宽度和 375 像素移动宽度无横向溢出。
- 页面普通文字达到 WCAG AA 对比度目标；键盘焦点清晰可见。

## 2. 显性需求与隐性需求

| 维度 | 设计要求 |
| --- | --- |
| 功能需求 | 保留全部现有接口、会话、任务、面试、报告和能力功能，只调整表现层 |
| 用户角色 | 当前聚焦学生用户；管理员页面不进入本次视觉范围 |
| 日常场景 | 查看下一步任务、咨询规划、更新画像、进行面试、复盘报告 |
| 异常场景 | AI 超时、报告尚未生成、历史数据为空、能力维度不足、流式回答中断 |
| 边界场景 | 超长 Markdown、长岗位名、仅 1–2 项能力、窄屏、历史记录较多 |
| 数据可信 | 明确状态、时间、版本和来源；不把 AI 建议表现为确定结论 |
| 情绪需求 | 专业但不压迫，给予行动感，不以夸张鼓励或装饰替代信息 |
| 品牌需求 | 蓝白企业感保持一致；机器人头像只用于 Agent 身份，不形成泛滥的 AI 视觉 |

## 3. 范围与优先级

### Must have

- 全局设计 Token、布局、导航、卡片、按钮、表单、表格和状态统一。
- Dashboard、职业画像、职业规划师、规划报告、成长任务、面试配置、面试过程、面试报告、面试记录、能力画像统一到 V2。
- 职业规划师和模拟面试官使用独立真实头像。
- 所有页面保留加载、空数据、成功和失败状态。
- 桌面、平板和移动端基本响应式可用。

### Should have

- 页面进入、卡片悬停、列表状态变化使用克制的 180–260ms 动效。
- 关键数据使用等宽数字特性，提升扫描与对比效率。
- 主要操作、危险操作、次要操作形成稳定层级。

### Could have

- 未来提供深色模式。
- 未来增加用户可配置的信息密度。
- 未来为图表提供数据下载和无障碍文本摘要。

### Won't have

- 本次不新增后台管理、RAG、语音或视频面试。
- 不改变接口字段、路由或业务状态机。
- 不引入新的 CSS 框架或平行组件库。
- 不使用大面积紫色渐变、霓虹光效、漂浮粒子或通用 AI 装饰。

## 4. 信息架构与核心任务流

```text
AI职途
├── 首页：目标、进度、下一步、路线、能力、最近面试
├── 我的职业画像：基础资料、技能、兴趣与目标
├── AI 助手
│   ├── AI职业规划师：新对话、历史会话、当前上下文、生成规划
│   └── AI模拟面试官：配置、进行、结束、报告
└── 成长中心
    ├── 我的学习计划：阶段、状态、任务操作
    ├── 能力画像：当前能力、趋势、评分记录
    └── 面试记录：历史记录、继续面试、查看报告
```

核心业务路径：

```text
完善职业画像
→ 生成职业规划
→ 执行成长任务
→ 开始模拟面试
→ 查看面试报告
→ 更新能力画像
→ 基于面试重新规划
```

导航不直接表现技术结构。用户首先看到“首页、画像、两个助手、成长中心”，并始终可通过顶栏识别当前位置。

## 5. 设计概念：理性职业操作台

### 5.1 视觉方向

整体采用**编辑式秩序 + 工业产品克制 + 清晰导视**。灵感方法取自 Dieter Rams 的功能优先、Otl Aicher 的导视清晰和 Massimo Vignelli 的网格纪律，仅转译原则，不复刻任何具体作品、构图、字体组合或品牌元素。

页面记忆点是“职业坐标”：左侧导航建立稳定坐标，页面标题说明当前位置，卡片中的细蓝色规则线与编号表示阶段和证据。视觉不追求未来感，而追求像一份可靠职业方案一样可扫描、可核对、可执行。

### 5.2 设计原则

1. **行动优先**：每个页面首先回答用户现在要做什么。
2. **结论先行**：报告和数据页面先展示结论，再展示依据与细节。
3. **克制分层**：白色表面、灰蓝画布、深蓝文字、品牌蓝动作形成四层关系。
4. **一个主操作**：同一视区只保留一个实心主按钮。
5. **身份可辨**：两个 Agent 通过头像、名称和职责区分，不通过不同炫彩主题区分。
6. **状态诚实**：加载、缺失、失败和未生成均明确说明，不使用空白占位。

## 7. 全局框架

### 7.1 桌面端

- 侧栏宽 248px，白色固定，品牌区与导航分区清晰。
- 顶栏高 64px，半透明白底配轻微模糊，仅承载当前位置、通知和用户菜单。
- 内容画布最大宽度 1480px；常规页面左右内边距 32px。
- 页面标题区包含章节编号/英文短标、H1、说明和一个主要状态或操作。

### 7.2 平板与移动端

- `< 1024px`：侧栏进入抽屉，双栏模块转单列。
- `< 768px`：页面内边距 16px，指标卡 2 列或 1 列，表格允许横向滚动。
- 移动端可点击区域至少 44×44px；聊天输入和主操作保持在可见区域。

### 8.2 AI职业规划师

```text
Agent 身份与职责                    [会话记录] [新建对话] [生成规划]
┌────────────────────────────────┬──────────────────┐
│ 主对话区                        │ 当前上下文        │

```

新进入页面保持空白新会话；首次发送后才创建服务端会话。历史会话通过抽屉主动加载。

### 8.3 模拟面试过程

```text
面试官头像 + 岗位/类型       题目进度 / 难度 / 状态       [结束面试]
┌────────────────────────────────────────────────────────┐
│ 面试问答时间线                                         │
│ 面试官问题                                             │
│                                        候选人回答       │
├────────────────────────────────────────────────────────┤
│ 回答输入；Ctrl + Enter 提交                 [提交回答]  │
└────────────────────────────────────────────────────────┘
```

面试过程中不显示内部评分、答案正确与否或完整标准答案。

### 8.4 报告页

- 第一层：岗位、版本/日期、综合结论、总分或匹配度、唯一主操作。
- 第二层：优势与风险，使用语义色左边线而非大面积彩色底。
- 第三层：能力图表与分项数据，图表旁保留可读数字。
- 第四层：路线、证据、建议及来源信息。

## 9. 页面级改造规格

| 页面 | V2 重点 |
| --- | --- |
| 登录/注册 | 深蓝品牌说明区 + 高对比白色表单；明确安全、成长闭环和切换状态 |
| Dashboard | 目标与下一步形成首要焦点；路线采用紧凑纵向结构；减少卡片空白 |
| 职业画像 | 资料完成度固定可见；表单按教育背景、目标、技能分组；保存反馈就近 |
| 职业规划师 | 规划师真实头像；工作台式对话与上下文；Markdown 保持文档化排版 |
| 规划报告 | 正式方案文档感；版本、结论、路线和重新规划关系明确 |
| 学习计划 | 状态和截止时间优先；筛选器稳定；完成操作不跳动布局 |
| 面试配置 | 面试官头像作为身份引导；配置项像简短面试邀请函而不是后台表单 |
| 面试过程 | 独立面试官头像；稳定高度；进度和结束动作清楚；隐藏内部评分 |
| 面试记录 | 岗位、时间、状态、成绩为主要扫描列；继续/报告动作明确 |
| 面试报告 | 总评先行，证据与改进建议随后；重新规划构成闭环主操作 |
| 能力画像 | 雷达/评分条与趋势统一蓝灰；少于 3 个维度自动改为评分条 |

## 10. 组件状态与交互

### 10.1 状态

- **加载**：内容骨架或局部 loading，避免整页长时间空白。
- **空数据**：说明为什么为空，并提供可执行入口。
- **失败**：保留已有内容；说明失败范围；提供重试，不暴露底层异常。
- **成功**：操作附近反馈，必要时同步全局用户状态。
- **禁用**：同时使用颜色、文字或原因提示表达，不只降低透明度。

### 10.2 动效

- 页面主要模块首次进入使用 240ms 以内的轻微上移淡入。
- 按钮、导航和可交互卡片使用 160ms 状态过渡。
- 流式回答、任务状态和进度变化不增加弹跳或光效。
- `prefers-reduced-motion: reduce` 时关闭非必要动画。

### 10.3 可访问性

- 可交互元素使用语义化按钮与表单标签。
- 键盘焦点使用 2px 蓝色轮廓，不能只依靠浏览器默认阴影。
- 图片提供准确 `alt`；纯装饰图标使用空替代文本或 `aria-hidden`。
- 状态不能仅依靠颜色；表格和图表提供文本数值。

## 11. Agent 头像规范

- 职业规划师使用“西装、简历与评估清单”机器人图片，强调职业咨询职责。
- 模拟面试官使用“圆形背景、日程与趋势图”机器人图片，强调面试流程与评估职责。
- 原图作为项目本地静态资源，不依赖临时路径或远程加载。
- 聊天头像裁切为正方形并使用圆角矩形；配置页可显示较大圆形裁切。
- 不把机器人图重复用作背景、水印、空状态或普通功能图标。

## 12. 实施与验收

### 实施顺序

1. 固化 V2 文档与 Design Tokens。
2. 重构全局布局、导航、表面层级和通用状态。
3. 重构 Dashboard 与两个 Agent 核心页面。
4. 收口画像、规划、任务、报告、记录和能力页面。
5. 在真实浏览器检查桌面与移动端，运行生产构建并清理遗留样式。

### 验收标准

1. 全站只有企业蓝白这一套主视觉，主流程没有紫色残留。
2. 页面层级一致，但不同业务页面仍能通过结构和内容形成辨识度。
3. 两个 Agent 头像正确、清晰、无拉伸，且职责不会混淆。
