## 额外发现并修复

全量保存技能会删除重建所有记录并重新设置 SELF 来源。即使用户只编辑一项技能，其余未变技能的面试来源与融合分数也会被清掉。

前端未修改技能时不调用替换接口；后端即使收到全量替换，也按同名技能的等级和分类是否变化判断，保留未变项的原分数与来源。主动改动的技能重新视为自评。清空技能不会删除既有面试评估历史，两者用途不同。

## 闭环要求的实际状态

| 要求 | 核查与边界 |
|---|---|
| 成果提交与任务验收 | 尚无代码链接、演示成果、验收记录模型和接口。任务完成不会直接写入能力评分，已明确其仅为学生标记；不能把该状态称为验证通过 |
| 评分关联回答证据和标准 | 面试消息保存题目分类、回答、内部评分与评价；报告 Prompt 已要求只评价实答内容、提前结束说明样本有限、不评分未覆盖领域。但没有报告分项到题目/回答的结构化关联，不能视为已完整实现 |
| 薄弱项专项训练与复测 | 现有重新规划参考旧任务和面试报告，Prompt 要求不重复已完成任务；缺少结构化能力→训练→成果→复测关系和跨版本去重/成果继承规则 |
| 岗位能力标准 | RAG 有后端能力框架与岗位差距知识，但没有统一实习/初级/进阶能力标准和评分算法。加强生成 Prompt 的基础优先要求，不冒充已实现岗位标准系统 |
| 实时评分与双模式 | 当前 README 和面试页面已经说明过程中不公开单题评分，内部评价用于结束后的报告；未发现本地现行页面承诺实时评分。练习/模拟双模式尚未实现 |

重新规划保存新版本时，会归档旧版本、生成一套新的待开始任务；旧任务保留在旧规划下，不会被删除。当前并非“已完成成果自动迁移”；模型不重复安排的 Prompt 也不是可靠的服务端去重规则。

## 上线与后续决策

本轮不部署、不推送、不合并远端。本地已有与远端分叉及用户未跟踪文档保持不变。

上线需更新后端与 Web 镜像，数据库结构无需迁移；历史生成的结论和任务日期不会被本轮自动修改。

继续实现完整闭环前，应先确认：成果如何提交和验收、延期如何处理、技能验证口径、重规划如何继承已完成成果、岗位标准来源，以及练习模式如何展示答案与反馈。确定后再以新增接口和数据库迁移落实，不能以静态 UI 或任意日期替代这些业务规则。
