大家好，我的作品是智职星职业规划平台。它面向职业方向和学习路径还不清晰的大学生，帮助大家把职业目标转化为可以执行、可以复盘的成长行动。

### 03　00:25–00:55：PPT 第 3 页，功能简介与业务闭环

**画面操作**

按业务过程指向职业画像、智能规划、成长任务、模拟面试、能力评估、动态再规划。最后停在底部知识检索、会话记忆和成长数据查询说明上。

**逐字稿**

平台从职业画像开始，记录学生的背景、技能和目标，再生成阶段规划，拆解为学习任务。学生通过模拟面试发现薄弱项，查看能力报告，并结合面试反馈重新规划。

职业规划师还可以查询个人成长记录，参考职业知识库提供建议。这样，学习行动和面试反馈就能连接起来，为下一步改进提供依据。

### 04　00:55–02:15：PPT 第 4 页，技术栈与公网部署

**画面操作**

不逐条读版本号。先指向后端的 Java 21，再指向智能能力与数据，之后指向前端和构建部署栏，最后指向底部公网地址。

**逐字稿**

技术部分，我重点介绍几个实际承担核心任务的设计。

首先是 Java 二十一的虚拟线程。当问题涉及多个知识主题时，系统先批量生成向量，再用虚拟线程并行查询 pgvector，合并并去重检索结果。它减少多个数据库查询依次等待的开销，优化的是检索阶段，不是大模型推理速度。

其次，Spring AI 统一接入聊天、向量化和工具调用。职业规划师通过只读工具查询任务、评分和面试摘要，用户身份由后端注入，模型不能指定其他用户。

MySQL 保存业务记录，pgvector 保存职业知识向量。知识回答经过证据检查，再展示并保存来源，方便后续回看。

前端使用 Vue 和 TypeScript 组织交互，ECharts 展示能力变化。Docker 多阶段构建分别生成前端页面和后端程序，Nginx 负责页面访问与接口转发。项目已经部署到公网，服务器无需安装 Java 或 Node 开发环境。

**逐字稿**

现在进入网页。成长首页汇总目标岗位、任务进度和面试反馈，让学生先看到下一步可以做什么。

在职业画像中，我填写专业、年级、目标岗位、技能水平和学习时间，系统据此生成个性化建议。这里的技能属于学生自评，页面明确标注待验证，不会直接当作已经证明的能力。

**逐字稿**

职业规划会结合画像和技能基础，给出阶段路线与待提升方向。这里的匹配分数是AI参考估计，不能作为岗位胜任认证。

进入学习任务后，可以查看具体行动并更新状态。我点击开始任务，这项任务就变为进行中。任务完成记录用于跟踪学习进度，学生标记完成也不代表已经通过能力验证。

### 07　03:20–04:00：模拟面试与面试报告

这里展示的是提前完成的一次面试。结束后，系统生成报告，分析已经回答的内容，给出优势、薄弱项和改进建议。评分用于辅助复盘，面试过程中不会实时公开单题分数，也不能替代真实招聘评价。

## 三、录制前准备

使用一个专用演示账号，所有展示内容来自它的真实操作记录，不使用他人的隐私资料。建议统一为 Java 后端实习方向，让画像、规划、任务、面试和问答自然衔接。

- 画像已有专业、年级、目标岗位、每周学习时间及至少三项技能。
- 规划提前生成，任务中保留至少一项待开始、一项进行中的任务。
- 已有一场包含实际回答的完整面试和报告；展示趋势需准备多次评估记录。
- 提前测试两个规划师问题，确认知识问题能展示来源，个人数据问题能读取真实记录。
- 需要展示重新规划结果时，提前在演示账号中录制，保留旧规划以展示版本变化。重新规划可能生成新任务，不要误认为旧任务状态会自动迁移。
- 浏览器提前登录，关闭通知与无关标签页。无需录制服务器登录，不展示密码、Token、密钥或 `.env`。
- PPT 四页讲完再进入网页，不另加技术页。英文名称不熟时提前练读。

AI 请求耗时受网络和供应商影响。等待可以剪短，但不能伪造回答、评分、来源或阶段动画。报告和趋势是功能效果展示，不是经实验测量的就业率或能力提升证明。

## 五、技术事实核对备忘，不作口播

以下信息用于回答评委追问。没有为本轮讲稿重新登录线上账号或执行 AI 请求，也没有修改业务代码或部署环境。

| 讲解点 | 项目中的真实用途与证据 | 不应夸大的结论 |
| --- | --- | --- |
| Java 21 虚拟线程 | `PgKnowledgeRetrievalService.createSearchFutures()` 在多个查询向量时调用 `Executors.newVirtualThreadPerTaskExecutor()`，并行执行独立的 PostgreSQL 检索；批量 Embedding 在这一步之前执行，结果按规划顺序合并 | 不是全站请求都改用虚拟线程，也不是并行调用多个大模型。没有本轮对照压测，不写具体加速倍数 |
| Spring AI | `CareerPlannerAgent`、`CareerReadTools` 使用 ChatClient、@Tool、ToolContext；Embedding 走 Spring AI 接口 | 只读工具不会自动创建或修改任务；身份来自后端，不来自模型参数 |
| RAG 与证据校验 | `GroundedCareerAnswerComposer`、`RagAnswerFactGuard` 处理知识事实与本轮证据；来源快照保存至消息 `references_json` | 引用一致性不等于所有知识绝对正确，也不表示已完全消除模型幻觉 |
| SSE | 规划师聊天展示真实处理阶段；知识与工具事实的回答先完整生成、校验，再发送；普通聊天保留原流式调用 | 不说所有回答都逐 Token 实时显示，也不以 SSE 冒充模型推理加速 |
| MySQL 与 pgvector | MySQL 保存画像、规划、任务、面试及聊天；独立 PostgreSQL 向量库保存职业知识 | 用户业务记录不是全部向量化存入知识库 |
| 前端与部署 | Vue/TypeScript 组织页面，ECharts 展示图表；前后端 Dockerfile 多阶段构建，Compose 管理 web、backend、mysql、pgvector，数据库命名卷持久化 | 多阶段构建减小运行环境范围，不宣称不用安装 Docker；公网部署不等于已完成高并发或高可用认证 |
| 动态再规划 | 现行入口依据面试报告发起重规划；旧版本保留 | 不说任意画像变化都会自动触发，也不说新版本自动继承已完成任务或成果验收 |
