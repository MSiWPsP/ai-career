# AI职途——企业蓝白风 UI 改版方案 v1.0

> 状态：视觉方向已确认，按阶段实施。本文只约束前端表现层，不改变 PRD、业务流程、API、数据库或 Agent 契约。
>
> 依据：《AI职途——大学生智能职业成长平台 PRD v1.0》《AI职途——功能模块设计文档 v1.0》《AI职途——页面与 UI 原型设计文档 v1.0》及当前 Vue 页面实现。原 UI 文档的页面结构和功能要求继续有效；若本方案获确认，仅以本文替代原文中蓝紫渐变等视觉风格建议。

## 1. 改版目标

把产品从“高饱和、强调 AI 氛围的学生工具”调整为“可信、专业、清晰的职业成长工作台”。视觉要有企业级产品的秩序感，同时保留面向大学生的易用与亲和，不做成传统 ERP 或招聘后台。

期望用户首先看到自己的目标、进度、待办和可执行建议，而不是渐变、光晕或“AI”装饰。AI 仍是关键能力，但应通过问题质量、规划内容和面试反馈体现，而非依赖视觉特效证明。

本轮未来实施范围限定为视觉样式、文案语气和必要的页面排版优化。保留当前路由、交互语义、数据结构、接口封装、状态管理、品牌 Logo 和主要信息架构。不同时引入新的业务功能、图表体系或设计框架。

## 2. 当前界面的主要问题

以下是基于现有 `ai-career-web/src` 的设计判断，不是功能缺陷结论：

| 现状 | 对体验的影响 | 改版方向 |
| --- | --- | --- |
| 全局主题以靛紫色为主，侧栏、登录页、首页和报告页叠加多处蓝紫渐变、径向光晕 | 注意力被装饰分散，正式感不足 | 以白、浅灰蓝、深蓝构成主色关系；渐变仅允许极少量品牌场景使用 |
| 首页多种彩色指标块与重点卡片同时争夺视觉中心 | 目标、进度和下一步行动的优先级不够明确 | 主目标一处突出，其余指标以统一卡片与数字层级呈现 |
| 聊天和面试中的紫色 AI 头像、绿色用户气泡、彩色背景并存 | 与其它业务页面像不同产品 | 统一为蓝白中性色聊天容器，角色靠对齐、标签和轻微底色区分 |
| 卡片阴影、圆角、按钮和标签的视觉权重不够统一 | 页面间有拼接感 | 建立同一套设计 Token 与组件状态规范 |
| 报告、规划、能力图表偏“展示页”而非“决策材料” | 阅读结论和找到行动项需要更多目光跳转 | 采用文档式报告、结论先行、依据与建议分层 |

## 3. 设计原则

1. **蓝白为骨架，内容为主角。** 大面积白色与浅灰蓝留白，蓝色用于导航选中、主按钮、关键数据和链接；不用大面积高亮渐变铺满页面。
2. **可信而不冰冷。** 标题、数据和说明保持克制；通过明确的状态、时间、来源和下一步动作建立信任，避免过度拟人化或营销化的文案。
3. **一个区域一个重点。** 每屏最多一个主操作和一个最强视觉焦点。次要操作退为描边、文字或菜单。
4. **先信息层级，后装饰。** 图表、任务、聊天和报告都优先优化扫描路径。阴影、插画、动效仅用于辅助理解。
5. **复用现有工程。** 沿用 Vue 3、Element Plus、ECharts、现有组件与 `@element-plus/icons-vue` 图标，不搭建平行 UI 架构。

## 4. 视觉规范草案

以下色值为实施起点，需在关键页面样张与浏览器中检查实际对比度后微调。语义色应按用途使用，不能为了丰富画面给每张卡片随机分色。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| 品牌主蓝 `primary` | `#1D4ED8` | 主按钮、选中态、重要链接 |
| 深蓝 `navy` | `#163B70` | 品牌标题、关键数据、局部重点背景 |
| 浅蓝 `primary-soft` | `#EAF2FF` | 选中导航、提示块、轻量高亮 |
| 页面背景 `canvas` | `#F5F8FC` | 主内容区 |
| 容器背景 `surface` | `#FFFFFF` | 侧栏、顶栏、卡片、弹窗 |
| 一级文字 `text` | `#182B45` | 标题、主要数值 |
| 二级文字 `text-muted` | `#5C6B7B` | 说明、辅助信息 |
| 分割线 `border` | `#DCE5EF` | 卡片、表格、输入框边界 |
| 成功 `success` | `#167D64` | 已完成、提升、成功反馈 |
| 警告 `warning` | `#A76514` | 待处理、临期提醒 |
| 危险 `danger` | `#C2413A` | 失败、删除、逾期 |

具体约束：

- 全站以纯色和轻边框为主。登录页可保留一块深蓝品牌区，但不使用多层径向光晕、漂浮圆环或网格装饰；主应用侧栏采用白底，而非整块深紫底。
- 卡片默认 10–12px 圆角、1px 边框；仅悬浮层或重点卡片使用轻阴影。按钮、输入框和标签圆角保持同一尺度，不普遍使用胶囊形。
- 间距以 8px 为基准，常用 8 / 16 / 24 / 32px；页面模块间距优先 24–32px，卡片内边距 20–24px。
- 中文正文优先系统字体（如苹方、微软雅黑），英文与数字使用一致的无衬线系统字形。页面标题 26–28px，模块标题 18–20px，正文 14–16px，辅助文字不小于 12px；行高保证中文长文可读。
- 动效只承担状态反馈：按钮悬停、折叠展开、加载与页面过渡控制在短时、低幅度范围；遵循系统减少动态效果偏好。
- 保留现有品牌 Logo。完整 Logo 适合登录页等宽阔区域；导航窄位使用图形标识与“AI职途”文字，不缩小完整带标语图至不可辨认。

## 5. 应用框架与组件

### 5.1 全局布局

- 推荐白色侧栏 + 白色顶栏 + 浅灰蓝内容底。侧栏约 232–240px，选中项使用浅蓝底、蓝色文字和 3px 左侧指示条；分组标题低对比、留足间距。
- 顶栏约 64–68px，页面名优先于冗长面包屑；通知、头像、账号菜单保持现有功能，避免多个装饰性图标抢占标题区。
- 主内容最大宽度约 1360–1440px，常规左右留白 24–32px。宽屏不无限拉伸正文；聊天与报告按各自阅读宽度处理。
- 1280px 为主要桌面检查宽度，1440px 和 1920px 检查空间分配；窄屏保持现有抽屉导航，低于约 768px 转单列，禁止横向溢出。

### 5.2 通用组件

- **卡片：** 普通信息卡白底细边，标题、值、说明、动作四层清晰；重点卡最多一张，且使用轻浅蓝底或深蓝标题区，不使用强渐变。
- **按钮：** 每个视区一个蓝色主按钮；次要操作描边/文字；危险操作仅在确认流程中使用红色。
- **表单：** 标签在输入上方，必填/错误/帮助文案就近呈现；聚焦态有可见蓝色轮廓，禁用态不能只靠降低透明度表达。
- **状态：** 加载、空数据、成功、失败均有文案与下一步动作；状态图标来自 Element Plus，避免 Emoji 作为正式功能图标。
- **标签和进度：** 颜色表达真实语义，不用绿色表示普通用户消息，也不把所有“AI 结果”标成紫色。
- **图表：** 主序列用蓝色，比较序列用灰蓝，目标线用深蓝虚线；红/橙/绿只表示明确的风险或状态。图表下保留数字和文字结论，不能只依靠颜色阅读。

## 6. 页面改造清单

| 页面/模块 | 建议表现 | 保留的核心能力 |
| --- | --- | --- |
| 登录/注册 | 左侧简洁品牌说明与完整 Logo，右侧白底表单；深蓝品牌区可选但不铺光晕，突出安全、清晰的入口 | 登录、注册与现有校验 |
| 首页 Dashboard | 顶部“当前目标 + 下一步建议”构成唯一视觉核心；进度、任务、能力摘要采用统一指标卡与清晰时间信息 | 当前画像、成长路线、任务及入口 |
| 职业画像 | 分区表单和完成度展示统一；减少大面积装饰，把缺失项和保存反馈放在可见位置 | 画像编辑、技能、头像等现有流程 |
| AI 职业规划师聊天 | 类工作台三栏关系：会话列表、主对话、当前上下文；主对话白底、蓝灰消息样式，输入区安静且固定；Markdown 内容按文档排版 | 新会话、历史、草稿、流式回复、上下文、会话管理 |
| 职业规划报告 | 类正式方案文档：岗位目标、匹配度、核心结论先行，阶段任务和依据随后；避免彩色横幅盖过内容 | 当前规划、历史、阶段与任务 |
| 学习计划 | 任务状态与截止时间比卡片装饰更突出；列表/卡片同一状态体系，完成动作明显 | 任务查看和状态更新 |
| 面试配置 | 目标岗位、面试类型和规则作为清楚的表单步骤；开始按钮为唯一主操作 | 面试配置与开始流程 |
| 面试进行页 | 模拟真实在线面试的安静环境：题号/进度/状态清晰，问答区保持稳定尺寸，结束面试需明确确认 | 提问、回答、追问、结束和中断处理 |
| 面试报告与记录 | 采用评估报告样式：总评、能力维度、证据、改进建议、下一步；历史列表突出岗位、时间和状态 | 报告查看与历史记录 |
| 能力画像 | 雷达/趋势图统一蓝灰配色，旁边给出可读的维度数值、变化说明与建议 | 能力分析与历史变化 |

页面文案也需同步收敛：功能名可以保留“AI 职业规划师”“AI 模拟面试官”，但减少装饰性英文眉题、拟人化提示和“智能光效”。AI 生成结论应明确是建议而非保证结果，具体行动项比宣传性口号更重要。

## 7. 实施顺序

### 阶段 0：样张确认

先制作首页、职业规划师聊天页、面试报告页三张代表性页面样张，覆盖数据概览、交互工作台与长文报告。确认白侧栏、主蓝强度、卡片密度和 Logo 用法，再批量推广；如仅靠代码预览也可，但应由用户先确认视觉方向。

### 阶段 1：全局基座与高频入口

调整 `src/styles/theme.css`、`src/layouts/AppLayout.vue`、登录页、首页及通用卡片/按钮状态。先解决全局紫色、深色侧栏、间距和导航层级；保持功能不变。此阶段结束后，全站即使尚有旧页面，也不应出现严重色彩冲突。

### 阶段 2：核心成长流程

依次改职业画像、职业规划师聊天、职业规划报告、学习计划、面试配置与进行页。重点检查长文本、Markdown、流式消息、表单错误、空会话和任务状态，避免视觉调整压缩有效内容或改变交互契约。

### 阶段 3：评估与全站收口

改面试报告、面试记录、能力画像与图表组件，统一响应式断点、弹窗、通知、空状态和细节文案；清理遗留紫色与装饰性渐变。最后完成多宽度和主要业务路径回归。

每阶段单独构建、浏览器检查和提交，避免一次性改动过大。前端运行 `npm run build`；有页面改动时检查 1280/1440/1920px 与手机窄屏、主要路径和控制台。若未来改到后端业务，再按仓库约定运行 `mvn clean test`，但本视觉方案不要求后端变更。

## 8. 验收标准

1. 首页、聊天、规划、面试、报告及能力页使用统一蓝白中性色体系；主路径无大面积紫色渐变、光晕、漂浮装饰。
2. 每页的标题、关键数据、主要操作和次要信息有稳定层级；首页能在短时间内定位“当前目标、进度、下一步”。
3. 登录、表单、聊天、任务、报告和图表在加载、空数据、成功、失败四种状态下均清晰可用。
4. 文字、按钮、焦点态和图表满足可读性要求；普通文字对比度以 WCAG AA 4.5:1 为目标，较大文字至少 3:1，不能仅靠颜色传达状态。
5. 1280px、1440px、1920px 和常见手机宽度无横向溢出；聊天窗口、表格、代码块与报告长文可正常滚动。
6. 键盘可到达导航、输入与主要操作；悬停/聚焦/禁用/错误状态一致；控制台无新增错误。
7. 原有路由、API 请求、会话与草稿、Markdown 安全过滤、面试流程和任务状态不因视觉改版回归。

## 9. 待确认的设计决策

- **侧栏：** 推荐白色侧栏配蓝色选中指示，以获得最稳定的企业蓝白效果；若希望品牌感更强，可在样张阶段比较深海军蓝侧栏，但不建议沿用深紫渐变。
- **品牌蓝：** 目前建议 `#1D4ED8`。若希望更沉稳，可往更低饱和的深蓝微调；实施前以样张和对比度检查定稿。
- **登录页品牌区：** 推荐简洁深蓝色块 + 现有 Logo，不再使用环形轨道与多层光晕；该页可比工作台略有品牌表现力。

视觉方向已按白色侧栏、`#1D4ED8` 品牌蓝和简洁深蓝登录品牌区确认。第一阶段从全局基座、登录页和首页开始；后续阶段仍按本文顺序推进。
