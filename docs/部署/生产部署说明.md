# AI职途生产部署说明

## 1. 部署结果

生产环境由根目录 `compose.yaml` 管理四个常驻服务和一个一次性任务：

```text
Internet :80
  -> web（非 root Nginx + Vue dist）
       -> /api/** -> backend:8080
  -> backend（非 root Java 21）
       -> mysql:3306
       -> pgvector:5432
       -> 百炼 Chat / Embedding API
       -> 阿里云 OSS

rag-import（显式运行，用完退出）
  -> pgvector
  -> 百炼 Embedding API
```

宿主机只发布 Web 的 80 端口。后端 8080、MySQL 3306 和 PostgreSQL 5432 均没有宿主机端口映射。MySQL 与 pgvector 分别使用命名卷持久化，只有 Compose 内部网络可以访问数据库。

常驻内存上限约为：MySQL 448 MiB、pgvector 384 MiB、backend 640 MiB、web 96 MiB，共 1.53 GiB。后端 JVM 默认 `-Xms128m -Xmx352m`、Metaspace 144 MiB、Direct Memory 64 MiB；MySQL 的 InnoDB Buffer Pool 为 128 MiB，pgvector 的 `shared_buffers` 为 128 MiB。其余空间留给操作系统、Docker 和页缓存，因此 2 GB Swap 是必要条件。

## 2. 服务器前提

- 64 位 Linux，2 核 2 GB 内存；
- **至少 2 GB Swap**；部署脚本会检查物理内存、当前可用内存和 Swap；
- Docker Engine 与 Docker Compose Plugin；
- 到百炼和 OSS 的网络连通；
- 防火墙只需对公网开放 80（以及运维所需的 SSH）。

Ubuntu 可参考以下方式创建 2 GB Swap（已有足量 Swap 时不要重复执行）：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

用 `free -h` 确认 Swap 生效后再部署。

## 3. 配置 `.env`

在仓库根目录执行：

```bash
cp .env.production.example .env
nano .env
```

`.env` 已被 Git 和 Docker 构建上下文排除，不得提交。脚本不会打印其中的值，并会拒绝空值、`__REQUIRED__` 占位符、非 `prod` Profile、过短 JWT 密钥以及不一致的 pgvector 账户。

必须填写：

| 变量 | 内容 |
|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL 容器 root 强随机密码，仅用于初始化和备份 |
| `DB_PASSWORD` | 后端专用 `ai_career` MySQL 用户的强随机密码 |
| `POSTGRES_PASSWORD` | 本机 pgvector 强随机密码 |
| `RAG_PG_PASSWORD` | 与 `POSTGRES_PASSWORD` 相同 |
| `AI_API_KEY` | 百炼聊天模型密钥 |
| `RAG_EMBEDDING_API_KEY` | 百炼 Embedding 密钥；可以与聊天密钥相同，但仍需显式填写 |
| `JWT_SECRET` | 至少 32 字符的随机密钥；上线后不要随意更换，否则现有登录失效 |
| `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` | 仅允许目标 Bucket 所需操作的 RAM 凭证 |

默认保留：

- `RAG_PG_URL=jdbc:postgresql://pgvector:5432/ai_career_rag`
- `DB_URL=jdbc:mysql://mysql:3306/ai_career?...`
- `MYSQL_DATABASE=ai_career`、`DB_USERNAME=ai_career`（后端不使用 root）
- `POSTGRES_DB=ai_career_rag`
- `RAG_KNOWLEDGE_DIR=/app/knowledge`
- `SPRING_PROFILES_ACTIVE=prod`
- `AI_RAG_IMPORT=false`（导入任务会在容器内单独覆盖为 `true`）
- `WEB_PORT=80`

生产 Profile 没有数据库密码、API Key 或 JWT Secret 默认值；缺少关键变量时应用或脚本会尽早失败。Swagger、Knife4j 在生产关闭，Actuator 只暴露 `/actuator/health`。

## 4. 首次部署

从仓库根目录执行：

```bash
bash deploy/deploy.sh --import-rag
```

脚本按顺序完成：

1. 检查 Docker、Compose、`.env`、内存和 Swap；
2. 执行 `docker compose config`；
3. 单独构建后端，再构建前端，避免 Maven 和 Node 同时争抢内存；默认跳过已在发布前执行的后端测试，只执行打包与 JAR 校验；如构建环境具备测试数据库，可设置 `DOCKER_RUN_TESTS=true`；
4. 校验运行镜像不存在 `application-local.yml`、`.env`、`target`、`dist`、源码依赖目录；
5. 依次启动并等待 MySQL、pgvector 健康；
6. 执行一次性 `rag-import`，导入失败立即中止；
7. 依次启动并等待 backend、web 健康；
8. 输出容器状态和访问地址。

`rag-import` 与 backend 使用同一镜像，但强制 `AI_RAG_ENABLED=true`、`AI_RAG_IMPORT=true` 和非 Web 模式。成功导入后 Spring 上下文主动关闭，容器以 0 退出；异常会非零退出。常规 Web 服务固定 `AI_RAG_IMPORT=false`，不会在重启时重复调用 Embedding。

业务数据和知识向量分别保存在命名卷 `ai-career-mysql-data`、`ai-career-pgvector-data`。脚本不执行 `down -v`、volume prune 或 system prune。

## 5. 常规更新与知识更新

使用服务器当前代码更新：

```bash
bash deploy/update.sh
```

先拉取远端再更新：

```bash
bash deploy/update.sh --pull
```

更新脚本构建带唯一标签的新镜像，确认两个数据库健康后依次替换 backend 和 web，并在检查健康后记录稳定版本。它不会删除 MySQL/pgvector 卷，也不会自动导入 RAG。

只有 `docs/知识库/catalog.json` 中受控知识版本发生变化时，才显式重新导入：

```bash
bash deploy/import-rag.sh
```

脚本会读取 `.deploy/current-version`，确保导入任务使用当前已经通过健康检查的稳定后端镜像，而不是 `.env` 中仅供预构建场景使用的静态标签。

导入实现按文档与版本幂等写入，并在新版本成功后切换 active 状态。Embedding 模型或维度变化需要先设计完整重建方案，不要直接复用旧表。

## 6. 回滚

更新失败时旧镜像不会被清理，脚本会提示：

```bash
bash deploy/rollback.sh
```

也可指定仍存在的镜像标签：

```bash
bash deploy/rollback.sh <APP_VERSION>
```

回滚只切换 backend/web 镜像，不回滚 MySQL 中已执行的 Flyway 迁移，也不修改两个数据库卷。因此上线迁移必须保持向后兼容；需要破坏性数据库回滚时必须另行制定备份恢复方案。

## 7. 低内存主机的预构建方案

主流程在服务器内构建并已限制 Maven/Node 堆，但依赖首次下载或宿主机后台进程仍可能造成 2 GB 主机压力。可以在开发机或 CI 使用相同源码先构建：

```bash
cp .env.production.example .env.build
APP_VERSION=release-20260927 docker compose --env-file .env.build build backend
APP_VERSION=release-20260927 docker compose --env-file .env.build build web
docker save ai-career-backend:release-20260927 ai-career-web:release-20260927 | gzip > ai-career-images.tar.gz
```

把镜像包传到服务器（不要传 `.env`），然后：

```bash
gzip -dc ai-career-images.tar.gz | docker load
# 在服务器 .env 中设置 APP_VERSION=release-20260927
bash deploy/deploy.sh --prebuilt --import-rag
```

也可以推送到私有镜像仓库后在服务器拉取同名标签。`--prebuilt` 会跳过构建，但仍执行镜像内容、资源、配置和健康检查。

## 8. 健康检查与验收

```bash
docker compose --env-file .env ps
curl -fsS http://127.0.0.1/healthz
curl -I http://127.0.0.1/login
```

应看到 mysql、pgvector、backend、web 均为 `healthy`。后端健康检查包含 Spring Boot 启动及主 MySQL DataSource 状态；外部 AI/Embedding 不计入健康状态，避免供应商短暂波动导致无限重启。RAG 检索自身继续按现有逻辑安全降级。

重点浏览器回归：

1. 注册、登录和刷新 `/dashboard` 等 History 路由；
2. 修改资料、上传不超过 5 MB 的 JPG/PNG/WebP/GIF 头像；
3. 职业画像、技能、规划与成长任务；
4. 模拟面试、报告、能力趋势和历史记录；
5. 职业规划师 SSE 持续输出至少数十秒，Nginx 不应整段缓冲；
6. RAG 来源卡片和 Tool Calling 事实；
7. 分别重启 mysql、pgvector 后，业务数据和知识数据仍在。

查看有限日志：

```bash
docker compose --env-file .env logs --tail=200 backend
docker compose --env-file .env logs --tail=100 web
```

日志使用 Docker `json-file` 轮转，每个容器最多 3 个 10 MB 文件。不要把 `.env` 内容或带凭证的命令输出粘贴到工单。

## 9. 数据备份

容器卷不是备份。上线后至少每天把 MySQL 逻辑备份和 pgvector 卷快照复制到服务器之外。手工导出 MySQL（密码只在容器环境内读取）可使用：

```bash
mkdir -p backups
docker compose --env-file .env exec -T mysql \
  sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers ai_career' \
  > "backups/ai_career-$(date +%Y%m%d-%H%M%S).sql"
```

备份目录不要提交 Git。恢复、定期保留策略和异机恢复演练应在正式开放用户前完成。

## 10. HTTPS

当前 Compose 只发布 HTTP 80，适合先由阿里云负载均衡、CDN/WAF 或宿主机统一网关终止 HTTPS。上游应把 HTTPS 请求转发到本机 80，并保留 `Host`、`X-Forwarded-For` 和 `X-Forwarded-Proto`。仓库不保存证书或私钥。

若直接在单机终止 TLS，建议另建只负责 443 的反向代理 Compose 扩展并把证书放在服务器受限目录，不要改动应用容器或把证书复制进镜像。SSE 路径仍需关闭代理缓冲并保留至少 180 秒读写超时。
