# AI职途：从零部署到 Linux 云服务器实战手册

> 适用项目：AI职途——大学生智能职业成长平台
>
> 适用环境：Ubuntu 24.04 LTS、2 核 CPU、2 GB 内存、至少 2 GB Swap
>
> 部署方式：Docker Engine + Docker Compose Plugin
>
> 项目目录示例：`/opt/ai-career/app`

本文面向第一次接触 Linux 和 Docker 的同学，按照一次完整生产部署的真实顺序，说明服务器需要准备什么、每条命令在做什么、怎样判断执行成功，以及发生问题后应该从哪里开始排查。

文中的 `<SERVER_IP>`、`<GIT_REPOSITORY_URL>` 和 `__REQUIRED__` 都是占位符，必须替换成自己的值。不要把服务器密码、`.env`、AI Key、OSS 密钥或数据库密码发到聊天、GitHub Issue、提交记录和截图中。

---

## 1. 最终部署结果

部署完成后，服务器上会运行四个常驻容器和一个按需执行的任务：

```text
浏览器
  │
  │ HTTP 80 / HTTPS 上游代理
  ▼
web：Nginx + Vue 静态页面
  ├── /               Vue 页面
  └── /api/**         反向代理到 backend:8080
                          │
                          ├── mysql:3306      业务数据
                          ├── pgvector:5432   RAG 向量数据
                          ├── 百炼            Chat / Embedding
                          └── 阿里云 OSS      用户头像

rag-import：仅在首次部署或知识库更新时执行，完成后退出
```

只有 Web 容器的 80 端口暴露给公网。后端 8080、MySQL 3306 和 PostgreSQL 5432 只在 Docker 内部网络中通信，不应该在云服务器安全组中开放。

服务器不需要安装 Java、Maven、Node.js、npm、MySQL 或 PostgreSQL。后端 JAR 和前端 `dist` 都在 Docker 多阶段构建过程中生成。

## 2. 部署前需要准备的东西

### 2.1 云服务器

- Ubuntu 24.04 LTS，64 位；
- 2 核 CPU、2 GB 内存；
- 系统盘建议至少 40 GB；
- 至少 2 GB Swap；
- 一个可以使用 `sudo` 的普通用户；
- 一个公网 IP；
- 云厂商安全组放行 TCP 22 和 TCP 80。

正式提供服务时还应准备域名和 HTTPS。初次部署可以先使用 `http://<SERVER_IP>` 验收。

### 2.2 项目文件

推荐把代码推送到私有或公开 Git 仓库，然后由服务器执行 `git clone`。仓库至少应包含：

```text
ai-career/
├── ai-career-server/
├── ai-career-web/
├── deploy/
├── docs/
├── compose.yaml
├── .dockerignore
└── .env.production.example
```

不要上传以下内容：

- 根目录 `.env`；
- `application-local.yml`；
- `target/`、`dist/`、`node_modules/`；
- 数据库文件、备份文件、日志和截图；
- SSH 私钥、服务器密码和任何云服务密钥。

### 2.3 外部服务凭证

需要提前准备：

- 百炼兼容 OpenAI 接口的 API Key；
- 百炼 Embedding API Key；
- 阿里云 OSS Bucket、Endpoint；
- 有目标 Bucket 上传和删除权限的 RAM AccessKey；
- 自己生成的 MySQL、PostgreSQL 和 JWT 强密码。

OSS AccessKey 建议使用专门的 RAM 用户和最小权限策略，不要使用阿里云主账号 AccessKey。

## 3. 第一次连接服务器

在本地终端连接服务器：

```bash
ssh ubuntu@<SERVER_IP>
```

第一次连接会询问是否信任服务器指纹。确认 IP 正确后输入 `yes`，再输入密码。输入密码时终端不会显示星号，这是正常的安全行为。

登录后先确认身份和系统：

```bash
whoami
hostname
uname -a
cat /etc/os-release
```

这些命令分别显示当前用户、主机名、内核与 CPU 架构、Linux 发行版。

### 3.1 设置时区

```bash
sudo timedatectl set-timezone Asia/Shanghai
timedatectl
```

成功时应该看到：

```text
Time zone: Asia/Shanghai (CST, +0800)
System clock synchronized: yes
```

### 3.2 更新系统软件包

```bash
sudo apt update
sudo apt upgrade -y
```

- `apt update` 只刷新软件包索引；
- `apt upgrade` 才安装可升级的软件包；
- `-y` 表示自动确认。

如果升级结果提示某些 SSH 会话正在使用旧二进制，通常不是故障。完成当前操作后重新 SSH 登录即可。不要在部署进行中贸然重启服务器。

## 4. 检查内存和 Swap

查看内存：

```bash
free -h
```

查看当前 Swap：

```bash
swapon --show
```

如果已经有不少于 2 GB 的 Swap，不要再次创建。只有 Swap 不足时才执行：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
grep -q '^/swapfile ' /etc/fstab || echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

可选地降低系统主动换页倾向：

```bash
echo 'vm.swappiness=20' | sudo tee /etc/sysctl.d/99-ai-career.conf
sudo sysctl --system
```

再次检查：

```bash
free -h
swapon --show
```

如果同时看到 `/swap.img` 和 `/swapfile`，表示系统拥有两个 Swap 文件，容量会相加。这不是故障；例如 1.9 GB 加 2 GB 显示为约 3.9 GB。只要磁盘空间充足，可以保持现状，不必为了“看起来重复”而删除。

## 5. 安装 Docker 和 Compose

本项目使用 `docker compose`，不是旧版的 `docker-compose`。以下步骤来自 [Docker 官方 Ubuntu 安装文档](https://docs.docker.com/engine/install/ubuntu/)。

### 5.1 添加 Docker 官方软件源

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

添加 APT 源：

```bash
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

安装 Docker：

```bash
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

### 5.2 验证安装

```bash
sudo systemctl status docker --no-pager
sudo docker run --rm hello-world
docker compose version
```

`hello-world` 打印成功提示、`docker compose version` 能显示版本，就说明 Engine 和 Compose Plugin 已可用。

### 5.3 允许当前用户使用 Docker

```bash
sudo usermod -aG docker "$USER"
```

然后退出 SSH：

```bash
exit
```

重新连接后检查：

```bash
id
docker version
docker compose version
```

`id` 的分组中应包含 `docker`。注意：[Docker 官方文档](https://docs.docker.com/engine/install/linux-postinstall/)明确指出，`docker` 组实际上拥有接近 root 的权限，只应该授予可信运维用户。

启用开机启动：

```bash
sudo systemctl enable docker.service
sudo systemctl enable containerd.service
```

## 6. 配置云安全组和防火墙

云厂商安全组建议：

| 端口 | 是否开放 | 用途 |
|---|---:|---|
| 22/TCP | 是，仅可信来源更好 | SSH 运维 |
| 80/TCP | 是 | 当前 HTTP 网站 |
| 443/TCP | 配置 HTTPS 后开放 | HTTPS 网站 |
| 8080/TCP | 否 | 后端只供 Compose 内网访问 |
| 3306/TCP | 否 | MySQL 只供 Compose 内网访问 |
| 5432/TCP | 否 | pgvector 只供 Compose 内网访问 |

查看 Ubuntu 防火墙：

```bash
sudo ufw status verbose
```

需要注意，Docker 发布端口可能绕过部分 UFW 规则，因此最重要的边界仍然是：`compose.yaml` 只发布 Web 端口，数据库和后端不配置 `ports`。

## 7. 把项目放到服务器

### 7.1 推荐方式：Git Clone

安装 Git：

```bash
sudo apt install -y git
```

创建部署目录并交给当前用户：

```bash
sudo mkdir -p /opt/ai-career
sudo chown "$USER":"$USER" /opt/ai-career
```

克隆项目：

```bash
git clone <GIT_REPOSITORY_URL> /opt/ai-career/app
cd /opt/ai-career/app
```

验证：

```bash
pwd
git status --short --branch
ls -la
```

如果是私有仓库，推荐配置 GitHub Deploy Key 或服务器 SSH Key。不要把 GitHub Token 直接写进 Clone URL，因为它可能进入 Shell 历史。

### 7.2 备选方式：SCP 上传

在本地终端执行：

```bash
scp -r ./ai-career ubuntu@<SERVER_IP>:/opt/ai-career/app
```

SCP 适合临时传输，但后续更新和版本追踪不如 Git 方便。上传前必须确保本地目录不包含 `.env`、`application-local.yml`、构建产物和密钥。

## 8. 创建生产环境配置

进入项目根目录：

```bash
cd /opt/ai-career/app
```

设置安全文件权限并复制模板：

```bash
umask 077
cp .env.production.example .env
chmod 600 .env
nano .env
```

`nano` 常用操作：

- `Ctrl + O`：保存；
- 按 Enter：确认文件名；
- `Ctrl + X`：退出；
- `Ctrl + W`：搜索变量名。

### 8.1 必须填写的配置

| 类别 | 变量 | 说明 |
|---|---|---|
| MySQL | `MYSQL_ROOT_PASSWORD` | MySQL root 初始化密码 |
| MySQL | `DB_PASSWORD` | 后端业务账户密码 |
| pgvector | `POSTGRES_PASSWORD` | PostgreSQL 密码 |
| pgvector | `RAG_PG_PASSWORD` | 必须与 `POSTGRES_PASSWORD` 一致 |
| AI | `AI_API_KEY` | 聊天模型 Key |
| AI | `RAG_EMBEDDING_API_KEY` | Embedding Key |
| JWT | `JWT_SECRET` | 至少 32 字符，决定登录令牌有效性 |
| OSS | `OSS_ACCESS_KEY_ID` | RAM 用户 AccessKey ID |
| OSS | `OSS_ACCESS_KEY_SECRET` | RAM 用户 AccessKey Secret |

可以在服务器生成随机密码，每次生成后立即保存到自己的密码管理器：

```bash
openssl rand -base64 32
openssl rand -hex 32
```

不要修改以下容器内地址：

```env
DB_URL=jdbc:mysql://mysql:3306/ai_career?...
RAG_PG_URL=jdbc:postgresql://pgvector:5432/ai_career_rag
RAG_KNOWLEDGE_DIR=/app/knowledge
```

这里的 `mysql` 和 `pgvector` 不是公网域名，而是 Compose 服务名。Docker 内置 DNS 会把它们解析到对应容器。

检查文件权限，但不要使用 `cat .env`：

```bash
ls -l .env
```

应该类似：

```text
-rw------- 1 ubuntu ubuntu ... .env
```

校验 Compose 配置：

```bash
docker compose --env-file .env config --quiet
```

没有输出并返回命令提示符通常表示通过。只执行 `docker compose --env-file .env` 会显示帮助信息，因为缺少 `config`、`ps`、`up` 等子命令；这不是服务故障。

## 9. 首次一键部署

在项目根目录执行：

```bash
bash deploy/deploy.sh --import-rag
```

这一个命令会按顺序完成：

1. 检查 Docker、Compose、`.env`、物理内存和 Swap；
2. 校验必填环境变量；
3. 校验 `compose.yaml`；
4. 在 Maven + JDK 21 构建阶段生成后端 JAR；
5. 在 Node 22 构建阶段执行 `npm ci` 和 `npm run build`；
6. 检查最终镜像中没有 `.env` 和 `application-local.yml`；
7. 启动 MySQL，等待健康；
8. 启动 pgvector，等待健康；
9. 执行一次性 RAG 导入；
10. 启动 backend，等待健康；
11. 启动 web，等待健康；
12. 记录稳定镜像版本并输出状态。

2 GB 服务器第一次构建需要下载 Maven、npm 和 Docker 镜像依赖，耗时可能较长。脚本刻意顺序构建后端和前端，避免二者同时占用内存。不要因为几分钟没有新输出就按 `Ctrl + C`。

### 为什么首次部署使用 `--import-rag`

首次部署时 pgvector 数据库没有职业知识向量，需要读取 `/app/knowledge` 中的受控文档并调用 Embedding API。导入完成后任务退出，不会常驻。

普通启动和普通更新都不会自动重复导入，避免重复调用 Embedding 和产生不必要费用。

## 10. 判断部署是否成功

### 10.1 查看容器状态

```bash
docker compose --env-file .env ps
```

应该看到：

```text
mysql       healthy
pgvector    healthy
backend     healthy
web         healthy
```

`rag-import` 不在常驻列表中是正常的，因为它执行完成后已经退出。

### 10.2 验证 Web 和后端健康

```bash
curl -fsS http://127.0.0.1/healthz
curl -I http://127.0.0.1/login
docker compose --env-file .env exec backend \
  curl -fsS http://127.0.0.1:8080/actuator/health
```

预期结果：

- `/healthz` 返回 `ok`；
- `/login` 返回 HTTP 200；
- Actuator 返回包含 `"status":"UP"` 的 JSON。

### 10.3 浏览器回归

打开：

```text
http://<SERVER_IP>
```

至少测试：

1. 注册、登录、退出和刷新页面；
2. 修改昵称并上传 JPG/PNG/WebP/GIF 头像；
3. 编辑职业画像和技能；
4. 查看 Dashboard；
5. 生成职业规划和成长任务；
6. 完成一次模拟面试并查看报告；
7. 给职业规划师发送 SSE 消息；
8. 检查 RAG 来源卡片；
9. 询问当前任务或能力评分，验证 Tool Calling；
10. 退出后重新登录，检查历史会话。

## 11. 日常查看和运维命令

以下命令都应在 `/opt/ai-career/app` 中执行。

### 11.1 查看状态

```bash
docker compose --env-file .env ps
docker stats --no-stream
free -h
df -h
```

- `docker compose ps`：查看本项目容器；
- `docker stats`：查看容器 CPU 和内存；
- `free -h`：查看系统内存与 Swap；
- `df -h`：查看磁盘空间。

### 11.2 查看日志

```bash
docker compose --env-file .env logs --tail=100 backend
docker compose --env-file .env logs --tail=100 web
docker compose --env-file .env logs --since=10m backend
docker compose --env-file .env logs -f backend
```

- `--tail=100`：只显示最后 100 行；
- `--since=10m`：只显示最近 10 分钟；
- `-f`：持续跟踪日志，按 `Ctrl + C` 退出，不会停止容器。

日志中可能出现请求 ID、用户 ID 或第三方错误响应。分享日志前要检查并遮盖 AccessKey、Token、手机号等信息。

### 11.3 重启单个服务

仅重启后端进程：

```bash
docker compose --env-file .env restart backend
```

如果修改了 `.env`，单纯 `restart` 不会重新创建容器，应该执行：

```bash
APP_VERSION=$(cat .deploy/current-version) \
docker compose --env-file .env up -d --no-deps --force-recreate backend
```

然后检查：

```bash
docker compose --env-file .env ps
docker compose --env-file .env logs --tail=80 backend
```

## 12. 发布新版本

### 12.1 从 GitHub 拉取并更新

先确认没有在服务器上手工修改受 Git 管理的文件：

```bash
git status --short --branch
```

然后执行：

```bash
bash deploy/update.sh --pull
```

脚本会：

- 使用 `git pull --ff-only` 拉取代码；
- 构建带唯一版本标签的新镜像；
- 保留旧镜像；
- 不删除 MySQL 和 pgvector 卷；
- 不自动重复导入 RAG；
- 先替换后端、健康后再替换 Web；
- 成功后记录当前稳定版本。

如果代码已经通过 SCP 放到服务器，使用：

```bash
bash deploy/update.sh
```

### 12.2 知识库更新

只有 `docs/知识库/catalog.json` 或受控知识文档版本变化时才执行：

```bash
bash deploy/import-rag.sh
```

不要把 `--import-rag` 当成每次启动的固定参数。

## 13. 回滚

更新失败时，脚本会保留旧镜像。回滚到上一稳定版本：

```bash
bash deploy/rollback.sh
```

指定镜像版本：

```bash
bash deploy/rollback.sh <APP_VERSION>
```

查看版本记录和本地镜像：

```bash
cat .deploy/current-version
cat .deploy/previous-version
docker images 'ai-career-*'
```

回滚只切换应用镜像，不会删除数据卷，也不会回滚已经执行的 Flyway 数据库迁移。因此数据库变更必须保持向后兼容。

## 14. 数据持久化与备份

MySQL 和 pgvector 使用 Docker 命名卷：

```bash
docker volume ls | grep ai-career
```

重新创建容器不会删除卷。以下命令禁止在生产环境随意执行：

```text
docker compose down -v
docker volume prune
docker system prune -a --volumes
```

它们可能删除数据库卷或回滚镜像。

手工备份 MySQL：

```bash
mkdir -p backups
chmod 700 backups
docker compose --env-file .env exec -T mysql \
  sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers ai_career' \
  > "backups/ai_career-$(date +%Y%m%d-%H%M%S).sql"
```

检查备份：

```bash
ls -lh backups
```

容器卷不是备份。正式上线后应把备份复制到另一台服务器或对象存储，并定期做恢复演练。

## 15. 常见问题排查

### 15.1 `docker compose` 只显示帮助

原因：命令缺少子命令。

错误示例：

```bash
docker compose --env-file .env
```

正确示例：

```bash
docker compose --env-file .env ps
docker compose --env-file .env config --quiet
```

### 15.2 容器显示 `unhealthy`

先看状态，再看对应日志：

```bash
docker compose --env-file .env ps
docker compose --env-file .env logs --tail=200 backend
```

如果是数据库容器：

```bash
docker compose --env-file .env logs --tail=200 mysql
docker compose --env-file .env logs --tail=200 pgvector
```

不要一看到失败就执行 `down -v`，那会把“应用启动问题”升级成“数据丢失问题”。

### 15.3 头像上传一直失败

查看最近日志：

```bash
docker compose --env-file .env logs --since=5m backend
```

常见错误：

```text
InvalidAccessKeyId
```

表示 OSS AccessKey 不存在、已禁用或填写错误。更新 `.env` 后必须使用 `--force-recreate backend` 重新创建后端容器。不要把新密钥粘贴到聊天中。

如果日志显示 `AccessDenied`，说明 Key 有效，但 RAM 权限不足；如果显示 Bucket 不存在或 Endpoint 不匹配，需要检查 Bucket 所在地域。

### 15.4 职业规划生成超时或 504

先定位 Web 和后端日志中的同一时间段：

```bash
docker compose --env-file .env logs --since=10m web
docker compose --env-file .env logs --since=10m backend
```

生产环境建议保持：

```env
AI_CAREER_PLAN_THINKING_ENABLED=false
AI_STREAM_TIMEOUT=180s
```

修改 `.env` 后需要重建后端容器。外部模型偶发超时不应该通过无限重启容器解决。

### 15.5 服务器内存不足或构建被杀死

```bash
free -h
swapon --show
docker stats --no-stream
dmesg -T | grep -Ei 'out of memory|oom|killed process' | tail -n 30
```

确认至少有 2 GB Swap，并使用项目脚本顺序构建。仍然不足时，在开发机或 CI 预构建镜像，再通过镜像仓库或 `docker save`/`docker load` 交付。

### 15.6 端口 80 被占用

```bash
sudo ss -lntp | grep ':80 '
```

先确认占用者，再决定是否停止旧 Web 服务。不要直接杀死不认识的系统进程。

### 15.7 修改 `.env` 后看起来没有生效

`docker compose restart` 只重启旧容器，不会应用新的环境变量。使用：

```bash
APP_VERSION=$(cat .deploy/current-version) \
docker compose --env-file .env up -d --no-deps --force-recreate backend
```

## 17. 一次完整部署的最短命令清单

完成服务器初始化和 Docker 安装后，真正部署项目的核心流程是：

```bash
sudo mkdir -p /opt/ai-career
sudo chown "$USER":"$USER" /opt/ai-career
git clone <GIT_REPOSITORY_URL> /opt/ai-career/app
cd /opt/ai-career/app

umask 077
cp .env.production.example .env
chmod 600 .env
nano .env

docker compose --env-file .env config --quiet
bash deploy/deploy.sh --import-rag

docker compose --env-file .env ps
curl -fsS http://127.0.0.1/healthz
```

之后通过 `http://<SERVER_IP>` 访问系统。普通代码更新使用：

```bash
cd /opt/ai-career/app
bash deploy/update.sh --pull
```

知识库变化才额外执行：

```bash
bash deploy/import-rag.sh
```

发生版本问题时回滚：

```bash
bash deploy/rollback.sh
```
