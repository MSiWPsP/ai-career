# RAG 回答校验与引用快照（2026-09-23）

## 本轮实现

- 职业规划师在有知识片段，或问题涉及性能/项目成果时，先完整生成回答并执行 `RagAnswerFactGuard`，通过后才发送 SSE `delta`。未通过时发送固定的测量与验证建议，不展示未经证实的结果句，也不附来源卡片。其他普通聊天保留原流式调用。
- 规则闸门覆盖无依据的性能百分比、QPS、耗时、IO 次数，以及“减少查询次数”“解决超时”“降低响应时间”等结果句；允许“可以尝试……并验证……”形式的计划。由于系统没有用户项目测量记录的可信存储，当前不把用户自述自动当成已验证结果。
- Flyway V7 为 `career_chat_message` 增加可空 `references_json`。新回答将服务端本轮实际交给 Agent 的引用快照与消息原子保存；历史查询和 SSE 幂等重放读取此字段。`NULL` 表示迁移前的旧消息，其文本尾注只能标为“历史来源（未验证）”。
- 个人画像回忆问题增加跳过知识检索规则，避免把无关的职业知识当成个人资料来源。

## 故障和并发验证

- 默认套件中的真实 TCP 连接失败测试覆盖 Embedding 端点不可达和 PostgreSQL 端点不可达；检索返回空依据。普通聊天的空依据路径由聊天服务测试覆盖。
- `AI_RAG_TIMEOUT_EVAL=true` 用本地 PostgreSQL 的 `pg_sleep` 验证 JDBC 查询超时会取消慢查询；尚需将超时直接注入完整检索加聊天链路。
- `AI_RAG_CONCURRENCY_EVAL=true`：4 工作线程、12 次真实检索，目标文档 12/12，P50 374 ms、P95/最大 923 ms。样本量不足以证明生产负载表现。
- 路由规则修改后重跑 `AI_RAG_EVAL=true` 的 80 题：路由 80/80，目标文档 Recall@5 60/60，目标章节 Recall@5 59/60，P50 304 ms、P95 671 ms；R053 仍未命中目标章节。
- 使用本地当前后端与 Vite 页面走真实浏览器：旧会话来源显示“历史来源（未验证）”；无压测数据问题在生成前校验后只显示固定安全建议、无引用；岗位能力问题完成后显示 4 条结构化来源，刷新后从历史会话恢复为“本次参考依据”。浏览器控制台无错误。浏览器验收产生的本地测试会话仅在开发数据库，不进入仓库。

## Spring AI 抽象评估

- 聊天已使用 Spring AI `ChatClient`、`.entity(...)` 和 ChatMemory；后续逐项事实输出可优先使用 `ChatClient.entity` 生成结构化声明、引用编号与原文短证据，再由服务端检查证据确属本轮 Prompt 片段，未通过时不发送正文。
- Embedding 目前保留窄 HTTP 适配器：本地百炼响应缺少 Spring AI 2.0.1 解析层要求的 `usage.prompt_tokens`。在兼容性修复并以真实模型复测前，直接替换 `EmbeddingModel` 会让检索全部降级。
- PGVector 当前使用独立 PostgreSQL 连接、显式失效过滤、导入版本切换和查询超时。若后续采用 Spring AI `PgVectorStore`，应先建立独立 `DataSource`/`VectorStore` Bean，在隔离环境对照 80 条检索集、导入幂等和故障超时，再删除原 SQL。此时直接换库会扩大质量门槛之外的变量。

## 后续结构化回答增量

原始回答抽样暴露 A003、A006 的通用建议超出来源。为此继续使用 Spring AI `ChatClient.entity(...)` 生成 `GroundedCareerAnswer`：事实部分只能提供本轮片段编号与逐字摘录，可选行动单列。服务端逐项检查编号和摘录确属本轮进入 Prompt 的对应片段；不合法的摘录和未经证实的行动会被丢弃，没有有效摘录时返回保守说明且无来源卡片。此机制不把模型自报的来源直接当成可信引用。当前没有可信的用户项目测量记录字段，因此输出结构不包含“已完成的项目结果”。

新来源快照补充文档版本、切片序号与片段正文 SHA-256；历史四字段快照仍可读取，其缺失的版本信息不能逆向补齐。该机制保证**展示的知识事实是本轮片段原文**，但原文知识的真实性、可选行动是否适合某个用户仍需人工与业务数据验证。结构化输出会降低自由表达，质量评测应同时看可用性和响应时间。
