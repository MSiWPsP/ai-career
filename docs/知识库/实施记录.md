# PGVector 首期实现记录

## 已定范围

- MySQL 继续保存业务数据；独立 PostgreSQL 只保存本项目受控知识切片和向量。用户画像、聊天、简历、面试记录不得入公共向量表。
- 向量模型默认 `text-embedding-v4`，维度固定 1024；文档与问题使用同一模型。PostgreSQL 的 `vector(1024)` 与模型绑定，修改模型或维度必须重建索引。
- 首期知识由 `catalog.json` 与同目录 Markdown 构成，导入通过本地启动开关触发，不开放管理 API 和普通用户上传。
- 先接职业规划师普通聊天与流式聊天。规划生成与模拟面试、MySQL 文档治理表、管理员权限和管理页面留待下一阶段；聊天消息已保存结构化引用快照。
- RAG 默认开启，可通过 `AI_RAG_ENABLED=false` 关闭。PostgreSQL 或 Embedding 未配置、不可用或超时时，应降级为原聊天；无结果不能伪造引用。

## 运行前提

1. 本机 PostgreSQL 已安装 pgvector 扩展，运行用户可在目标数据库执行 `CREATE EXTENSION IF NOT EXISTS vector`、建表和建索引。
2. 建议单独创建 `ai_career_rag` 数据库及最小权限用户；开发环境可以暂用本机账户，但不要把密码写进 `application.yml`、源码或 Git。
3. 通过环境变量提供 `RAG_PG_URL`、`RAG_PG_USERNAME`、`RAG_PG_PASSWORD`、`RAG_EMBEDDING_API_KEY`。如与聊天共用百炼密钥，可省略最后一个变量并使用 `AI_API_KEY`；密钥必须拥有向量模型调用权限。
4. 在 `ai-career-server` 目录运行，默认文档目录为 `../docs/知识库`。部署为 JAR 时需显式设置 `RAG_KNOWLEDGE_DIR` 指向受控目录。
5. 设置 `AI_RAG_ENABLED=true` 和 `AI_RAG_IMPORT=true`，在 `ai-career-server` 目录运行 `mvn spring-boot:run '-Dspring-boot.run.arguments=--spring.main.web-application-type=none'` 完成独立导入；完成后关闭 `AI_RAG_IMPORT`，保留 `AI_RAG_ENABLED=true` 再启动日常 Web 服务。不要让导入进程同时对外处理聊天请求。

## 目前限制与验收

- 这是可回滚的本地验证切片，不是设计文档第 25 节的“生产第一版”。首批只有 5 篇原创文档；初始 15 条评测问题已扩充为 80 条，但仍需真实用户措辞、回答与引用盲审、延迟和提示注入的进一步验证。
- 原创文档不是招聘标准，复审与失效日期要维护。过期文档应停止参与检索。
- 暂不支持上传、异步任务和可视化管理；导入失败应查看服务端摘要日志，修复后再次导入。
- 当前百炼响应在本机未返回 Spring AI 2.0.1 `OpenAiEmbeddingModel` 会读取的 `usage.prompt_tokens`。业务检索和导入已统一依赖 Spring AI `EmbeddingModel`；项目只保留一个继承 `AbstractEmbeddingModel` 的薄兼容实现，复用 Spring AI 的 OpenAI SDK、请求选项、批量输入和返回类型，并在响应转换时跳过缺失的 usage。超时和重试分别由 `RAG_EMBEDDING_TIMEOUT_SECONDS`、`RAG_EMBEDDING_MAX_RETRIES` 配置。

## 2026-09-24 回答质量门槛与多意图检索

- RAG 回答先由 Spring AI `ChatClient.entity(...)` 生成结构化草稿，再由服务端逐字核验摘录确实存在于本轮实际进入 Prompt 的切片中；建议与已发生结果分开表达，无测量证据时不能交付性能数字或完成式结果。
- Flyway V7 为聊天消息增加 `references_json`，保存文档 ID、版本、切片序号和内容 SHA-256。实时来源和历史回放均使用服务端结构化快照，旧文本尾注不作为审计级证明。
- 新增本地确定性查询规划器，为学习路线、岗位能力、简历/投递/面试等多意图问题补充最多 3 条查询。多条查询使用 Spring AI `EmbeddingModel` 一次批量向量化，PostgreSQL 检索使用虚拟线程并行执行，结果按规划顺序合并。
- 5 篇知识文档共 24 个有效切片。80 条检索评测路由 80/80、目标文档 Recall@5 60/60、目标章节 Recall@5 59/60，P50 246 ms、P95 628 ms。
- 12 条真实模型回答的关键事实与来源一致 12/12，评测目标完整覆盖 11/12；4 工作线程、12 次真实检索成功 12/12，P50 559 ms、P95/最大 1240 ms。Embedding 不可用、PostgreSQL 不可用和查询超时均验证普通聊天可继续完成且不显示来源。详见 [RAG 质量复核与故障验证](RAG质量复核与故障验证-2026-09-24.md)。
- 质量门槛通过后可进入管理员知识文档管理接口。职业规划生成和模拟面试接入仍应在管理链路完成后分阶段推进。

## 2026-09-26 Spring AI 链路复核

- 删除业务自建的 JDK `HttpClient` Embedding 客户端。检索服务与知识导入器只依赖 Spring AI `EmbeddingModel`，导入时用 `embed(List<String>)` 批量向量化同一文档的切片。
- 当前百炼接口缺少 usage 字段，不能直接实例化 Spring AI 2.0.1 `OpenAiEmbeddingModel`。`CompatibleOpenAiEmbeddingModel` 只处理这一处供应商兼容差异；连接、超时、重试、请求参数和响应对象复用 Spring AI 内置 OpenAI SDK。
- 真实百炼 + PostgreSQL 冒烟通过，10 个知识问题目标文档召回 10/10；5 篇文档的 24 个切片也已通过批量 Embedding 重新导入。
- `PgVectorStore`、RAG Advisor 与本地检索编排的取舍和后续迁移条件见 [Spring AI RAG 链路复核](Spring-AI-RAG链路复核-2026-09-26.md)。

## 流式聊天与前端可见性

- SSE 新增 `phase` 事件。只有本轮符合检索条件且 RAG 已启用时，才先发送 `KNOWLEDGE_RETRIEVAL`，然后执行 Embedding/PGVector 检索；生成开始时发送 `GENERATING`。前端不再用定时器模拟阶段，也不会在未收到检索事件时显示知识库步骤。
- `done` 返回 `ragApplied` 和实际进入本轮 Prompt 的 `references`。前端把来源作为独立卡片展示；无结果或检索降级时不显示来源。
- 服务端在 `chat_message.references_json` 中持久化引用快照，历史回放从结构化字段恢复来源卡片。旧历史尾注仅用于兼容显示，不作为可信来源证明。
- RAG 默认开启；本地开发应在被忽略的 `application-local.yml` 或环境变量中配置 PostgreSQL 凭证，修改后必须重启后端。提问如“Java 后端岗位需要哪些核心能力？”会触发检索，前端在回答流中和完成后持续展示 `RAG 知识库` 标识；纯会话回忆类问题按规则跳过检索。

## 选型依据

- [Spring AI 2.0.1 Embedding 配置](https://docs.spring.io/spring-ai/reference/api/embeddings/openai-embeddings.html)支持对聊天与向量调用分别配置 base URL、API Key 和模型。
- [阿里云百炼 Embedding 接口](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)说明 `text-embedding-v4` 支持 OpenAI 兼容接口及 1024 维输出。
- [Spring AI PGVector 参考](https://docs.spring.io/spring-ai/reference/api/vectordbs/pgvector.html)说明 pgvector 扩展、余弦距离索引及维度约束。当前检索层保留独立 PostgreSQL 连接，以避免向量库自动装配替换现有 MySQL 主数据源；回答结构化生成使用 Spring AI `ChatClient` API。
