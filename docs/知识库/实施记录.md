# PGVector 首期实现记录

## 已定范围

- MySQL 继续保存业务数据；独立 PostgreSQL 只保存本项目受控知识切片和向量。用户画像、聊天、简历、面试记录不得入公共向量表。
- 向量模型默认 `text-embedding-v4`，维度固定 1024；文档与问题使用同一模型。PostgreSQL 的 `vector(1024)` 与模型绑定，修改模型或维度必须重建索引。
- 首期知识由 `catalog.json` 与同目录 Markdown 构成，导入通过本地启动开关触发，不开放管理 API 和普通用户上传。
- 先接职业规划师普通聊天与流式聊天。规划生成与模拟面试、MySQL 文档治理表、管理员权限、结构化引用审计和管理页面留待下一阶段。
- 默认关闭 RAG。开启后检索失败应降级为原聊天；无结果不能伪造引用。

## 运行前提

1. 本机 PostgreSQL 已安装 pgvector 扩展，运行用户可在目标数据库执行 `CREATE EXTENSION IF NOT EXISTS vector`、建表和建索引。
2. 建议单独创建 `ai_career_rag` 数据库及最小权限用户；开发环境可以暂用本机账户，但不要把密码写进 `application.yml`、源码或 Git。
3. 通过环境变量提供 `RAG_PG_URL`、`RAG_PG_USERNAME`、`RAG_PG_PASSWORD`、`RAG_EMBEDDING_API_KEY`。如与聊天共用百炼密钥，可省略最后一个变量并使用 `AI_API_KEY`；密钥必须拥有向量模型调用权限。
4. 在 `ai-career-server` 目录运行，默认文档目录为 `../docs/知识库`。部署为 JAR 时需显式设置 `RAG_KNOWLEDGE_DIR` 指向受控目录。
5. 设置 `AI_RAG_ENABLED=true` 和 `AI_RAG_IMPORT=true`，在 `ai-career-server` 目录运行 `mvn spring-boot:run '-Dspring-boot.run.arguments=--spring.main.web-application-type=none'` 完成独立导入；完成后关闭 `AI_RAG_IMPORT`，保留 `AI_RAG_ENABLED=true` 再启动日常 Web 服务。不要让导入进程同时对外处理聊天请求。

## 目前限制与验收

- 这是可回滚的本地验证切片，不是设计文档第 25 节的“生产第一版”。首批只有 5 篇原创文档、15 条初始评测问题；上线前应扩充并人工标注至至少 80 条，检验 Recall@5、引用准确率、延迟及提示注入。
- 原创文档不是招聘标准，复审与失效日期要维护。过期文档应停止参与检索。
- 暂不支持上传、异步任务和可视化管理；导入失败应查看服务端摘要日志，修复后再次导入。
- 当前百炼响应在本机未返回 Spring AI 2.0.1 适配层要求的 `usage.prompt_tokens`；因此 Embedding 使用窄 HTTP 兼容客户端，只解析 `data[0].embedding`，并设置 15 秒请求超时。聊天仍使用 Spring AI。

## 2026-09-20 本机验证

- 本机新建 `ai_career_rag` 数据库并启用 pgvector；未改动现有 MySQL 业务表。
- 5 篇原创文档最终导入为 22 个有效切片；其中 2 篇更新为版本 2，旧版 8 个切片保留但已停用。相同版本重复导入不会增加切片。
- 启用 RAG 的真实 Embedding + PGVector 冒烟测试通过。首批 10 个知识问题的目标文档召回 10/10，5 个无需检索问题跳过 5/5；样本太小且来自自编语料，不能视为生产发布门槛。
- 本地数据库账户仅用于开发验证；生产环境需独立最小权限账户、备份、监控与正式评测。

## 流式聊天与前端可见性

- SSE 新增 `phase` 事件。只有本轮符合检索条件且 RAG 已启用时，才先发送 `KNOWLEDGE_RETRIEVAL`，然后执行 Embedding/PGVector 检索；生成开始时发送 `GENERATING`。前端不再用定时器模拟阶段，也不会在未收到检索事件时显示知识库步骤。
- `done` 返回 `ragApplied` 和实际进入本轮 Prompt 的 `references`。前端把来源作为独立卡片展示；无结果或检索降级时不显示来源。
- 服务端仍在历史消息中持久化引用尾注，并加内部标记供前端恢复历史来源卡片。未带此标记的旧历史回答保持原样；非流式接口暂未扩展结构化来源字段。
- 本地开发可在被忽略的 `application-local.yml` 中开启 `ai.rag.enabled` 并配置 PostgreSQL 凭证；修改后必须重启后端。提问如“Java 后端岗位需要哪些核心能力？”会触发检索，前端在回答流中和完成后持续展示 `RAG 知识库` 标识；纯会话回忆类问题按规则跳过检索。

## 选型依据

- [Spring AI 2.0.1 Embedding 配置](https://docs.spring.io/spring-ai/reference/api/embeddings/openai-embeddings.html)支持对聊天与向量调用分别配置 base URL、API Key 和模型。
- [阿里云百炼 Embedding 接口](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)说明 `text-embedding-v4` 支持 OpenAI 兼容接口及 1024 维输出。
- [Spring AI PGVector 参考](https://docs.spring.io/spring-ai/reference/api/vectordbs/pgvector.html)说明 pgvector 扩展、余弦距离索引及维度约束。此原型使用独立 PostgreSQL 连接和显式 SQL，以避免 Spring AI 自动装配将现有 MySQL 主数据源替换掉。
